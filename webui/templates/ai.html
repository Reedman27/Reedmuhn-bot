Use the API's /v1 base. ReedMuhn appends /chat/completions.

The saved key is never displayed back in the dashboard.

When enabled, ReedMuhn sends the most recent messages from the channel where /ask was run to the AI provider, so it can answer questions about the ongoing conversation. This sends real member messages to your configured third-party provider — leave it off unless you trust that provider and have told your members.

When enabled, ReedMuhn stores a rolling searchable copy of channel messages in the shared SQLite database so /ask can answer questions about earlier conversations. It is off by default. Only enable this where your server's members are comfortable with message indexing.

Connection presets

Channel indexing and live channel context are separate settings. Indexing does not automatically send your entire database to the AI provider; /ask only sends the small set of indexed messages that match the question.

OpenAI: https://api.openai.com/v1 · Groq: https://api.groq.com/openai/v1 · Ollama: http://host.docker.internal:11434/v1 when that hostname is available from your Docker setup.

Providers that speak the OpenAI chat-completions format work without another SDK. Keep your API key private and only enable AI in servers where you trust the configured endpoint.
