# Dashboard rework audit - 2026-11-02

Scope: the dashboard-rework ZIP (OAuth2, multi-server access, new navigation/layout).
Result: 693 existing tests passed, but **none of them exercised OAuth** - they all ran in
local-password mode, where every server is visible. 22 new tests (`webui/tests/test_oauth_multiguild.py`)
now run real OAuth against a fake Discord API. Total: 715 passing.

## Bugs found and fixed

| # | Severity | Problem | Fix |
|---|----------|---------|-----|
| 1 | High | `/dashboard-log` showed **every** login IP and every action in **every** server to any signed-in Discord user, including people with no server access | Log is scoped: own sign-ins only; actions only for servers you manage; other admins' IPs hidden. Actions now record which Discord user did them |
| 2 | High | Origin check compared against `http://host` (what the app sees behind Tailscale Funnel) vs the browser's `https://host`, so every POST would 403 | Also accepts the origin of `DISCORD_REDIRECT_URI` |
| 3 | High | Comment promised a guild-list cache; there was none. Every page view and POST called Discord, which rate-limits, which then bounced managers out as "no permission" | 60 s per-session cache, 5 min stale grace on 429/outage, fail closed with no cache |
| 4 | High | Concurrent requests refreshed the same rotating refresh token, killing the session | Per-session lock |
| 5 | Medium | OAuth tokens of expired sessions stayed in SQLite forever | Purged with the session |
| 6 | Medium | Logout only deleted local rows; Discord kept the tokens valid | Best-effort revoke at Discord on logout |
| 7 | Medium | Revoked grant (400/401) just returned "no servers" forever | Session ended, user sent to login |
| 8 | Medium | No HTTP timeouts (aiohttp default is 5 min) | 10 s timeout on every Discord call |
| 9 | Low | Non-ASCII `state` raised TypeError (500) in the callback | Byte comparison |
| 10 | Low | Callback didn't verify the `guilds` scope was granted | Requires `identify` + `guilds` |
| 11 | Low | `/dashboard-settings` could show a server the user lost access to | Re-checked |
| 12 | Low | Behind a proxy all IPs were the proxy's (log + lockout useless) | Opt-in `WEBUI_TRUST_PROXY=1` |

## Layout / sorting fixes
- "Dashboard Settings" lived in a separate grid row, i.e. at the very bottom of long pages. It is now pinned inside the sticky sidebar.
- Dead duplicate brand/server-name markup removed from the sidebar.
- 5 duplicated nav icons replaced (Raid/AutoMod, Logging/Staff Activity, Polls/Dashboard, Leveling/Analytics, Counting/Counters).
- Filing: **Counting Game** and **Music** moved to Fun & Economy; **Live Counters** (voice-channel renamers) moved to Server Tools. Revert = one line each in `templates/base.html`.
- Orphaned `templates/extras.html` (the old "Extras" page, unreachable) deleted.
- Dashboard Log page text no longer claims a shared password.

## Docs that were wrong
- `SECURITY_AUDIT_REPORT.md` said the Lavalink default password was removed. It was not (compose, `cogs/music.py`, `lavalink/application.yml` and a test all still use it). Corrected. Low risk since Lavalink isn't published, but set `LAVALINK_PASSWORD`.

## Verified OK
Every nav link has a route and matching active id; no inline styles (CSP-safe); ID-based mutations (tickets, polls, reports, suggestions, warns, cases, giveaways, temp voice) are all guild-scoped, so Server A's admin can't touch Server B's rows by guessing IDs.

## Still not verified (needs you)
- A live run against real Discord with two accounts and two servers.
- Docker/Compose was not run here.
- OAuth tokens are plaintext in `bot.db` (documented); consider disk encryption/backup hygiene.
- Bot-side (non-dashboard) per-guild isolation was not audited line by line.

## Deploying behind Tailscale Funnel
.env: `DISCORD_REDIRECT_URI=https://<funnel-host>/auth/discord/callback`, `WEBUI_HTTPS_ONLY=1`,
`WEBUI_TRUST_PROXY=1`, `WEBUI_BIND_ADDRESS=127.0.0.1`. Funnel to `http://127.0.0.1:8490`.
